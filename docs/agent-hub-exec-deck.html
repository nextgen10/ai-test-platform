What it is   02 / 06

One control plane where agents become reusable assets.

Not a chatbot and not an application. A place where agent work is registered, governed, executed and evidenced the same way every time.

Bring capability in as assets

Agents, skills, prompts and workflows live in one registry as versioned files. Adding a capability means publishing files the platform validates — not writing a new system.

Run it all the same way

Every request gets its own isolated, disposable job with enforced limits, timeouts and cancellation. No shared sessions, and no one request able to affect another.

Consume it two ways

A single console runs any registered workflow. When a use case deserves its own screen — approvals, scorecards, exports — it declares one and the platform surfaces it.

The platform knows how to run work. The workflow knows the domain. That separation is the whole idea.

Control   03 / 06

Governed by design, not by policy document.

A person stays accountable

Where the work warrants it, nothing proceeds until a named reviewer approves — and the refusal is recorded too.

Isolated by default

One disposable job per request. No shared agent session, so no request can see or affect another's data.

Nothing trusted blind

The model does not get the last word: output must satisfy an agreed structure and business rules to complete.

Evidence, not assurances

Every state change, version and input–output fingerprint is recorded, so any result can be explained months later.

The ask   06 / 06

Make Agent HUB the default place agent work lands.

01

Endorse it as the standard

When a team has an agentic use case, the first question becomes “what does this look like on the HUB?” rather than “what stack shall we build?”

02

Route the next use cases through it

Name two or three candidates so the platform is proven across domains, not just in quality engineering.

03

Back the hardening before wide rollout

The platform is production-shaped, and the remaining gaps are known, small and worth closing deliberately.

What we would close first

  • Sign-in and identity. There is deliberately no login today; access is controlled by network isolation. SSO is the first item before any wider audience.
  • Managed secrets. Credentials sit in Kubernetes secrets; a managed vault is the next step.
  • Quality over time. Every run is scored, but we do not yet track whether quality moves release over release.
  • Artifact storage. Results sit on cluster storage today; object storage is the scale answer.

The expensive part — isolation, governance, audit, execution — is built and running. What we are asking for is the mandate to make it the shared foundation, so the next use case costs a workflow file instead of a project.
