The architectural choice
02 / 05

A platform, not a new product per idea.

Most “AI initiatives” become a chat window or a purpose-built screen. The next request then becomes another release. Agent HUB stops that pattern.

Typical approach

One use case = one product

  • Hardcoded into the application. A new use case is a release.
  • Work lives in an ephemeral transcript. Nothing to audit.
  • A long-lived shared process. A crash lands on everyone.
  • Human control is informal. No structured gate.
Agent HUB

One plane = many use cases

  • A file in the registry. A new workflow is live with no redeploy.
  • One job per run: versioned artifacts and a full event trail.
  • 1 request = 1 isolated job. Sandboxed. Bounded filesystem.
  • Workflows can pause for approval. The decision is recorded.

Use cases are installations
04 / 05

One example. The same pattern, repeatedly.

Test Design is one workflow installed on the plane — not the product. The next use case is another file, not another platform.

Example · Custom UI

Test Design & Evaluation

Unstructured requirement → INVEST gate → coverage matrix → generated suite → 5-D evaluation. Five agents, one job, a dedicated surface because this work needs one. The Console can still run the same workflow.

How the next one arrives

Workflow Builder

Describe a workflow in English. Agents design, write, and install it into the registry — live, no redeploy.

Same plane, other domains

Already the pattern

Document OCR. Incident post-mortem. Payments, IAM, trading skills as files. Each is a catalog entry, not a new product line.

The question is not “can we build another AI app?” It is “can we install another workflow?”

What this means
05 / 05

Fund the plane. Scale the catalog.

Leadership gets reuse, control, and evidence — without a new build for every request from the business.

01 · Reuse

Stop paying for a new product each time

The Console already runs anything in the registry. A Custom UI is optional, and only when the work needs its own surface.

02 · Govern

Every run is accountable

One job, isolated execution, approval gates when required, and an audit trail. Nothing lives only in a chat.

03 · Grow

Add use cases without a release train

Drop a file, or describe it in English. The platform does not change. The catalog does.
